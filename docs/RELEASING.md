# 发版清单

每次发版（包括小版本）都按这个顺序逐项做，做完一项勾一项。

## 1. 代码和测试

- [ ] `npm test` 全部通过，记下用例数。
- [ ] 在隔离的 `DSH_HOME` 下实测新功能（不要用 3999 端口那个，也不要用日常 profile）。
- [ ] 实测中发现并修复的问题，写进 `docs/DESIGN.md` 对应版本的「实测记录」。

## 2. 文档（README 要整篇过一遍，不能只加一节）

README 从头到尾每一节都要对照新功能检查：

- [ ] 顶部一句话介绍、首图：新功能是主角的话要换。
- [ ] 测试徽章的用例数。
- [ ] 「为什么要有拼图台」「核心理念」：新功能解决了新问题、带来新原则的，要补上。
- [ ] 「快速开始」：安装步骤；从旧版本升级的方法；打开后默认看到什么。
- [ ] 「界面一览」：整体布局说明；新功能单独一节并配截图；老的小节里因为新功能而改变的入口和操作。
- [ ] 「安全模型」：新的读写和新的操作要各占一行。
- [ ] 「配置」：新增的或含义变了的配置项。
- [ ] 「常见问题」：新功能最可能被问到的问题。
- [ ] 「工作原理」：新模块、新接口、新用到的 DSH 能力。
- [ ] 「路线图」：勾掉已完成的。
- [ ] 「参与开发」：测试用例数。

其他文档：

- [ ] `docs/DESIGN.md`：新版本的设计、DSH 源码出处、实测记录、已知限制；文首状态行。
- [ ] `CHANGELOG.md`：新版本条目。
- [ ] `package.json` 的 `version`。
- [ ] `docs/images/` 的截图，在 1440×900 下拍。

## 3. 发布

- [ ] 提交，`git tag -a vX.Y.Z`，推送 `main` 和标签。
- [ ] GitHub Release：标题「vX.Y.Z · 一句话」，正文写新增、修复、安装 / 升级，并附截图。
- [ ] 打开仓库首页和 Release 页面，确认 README、图片、Latest 标记都正确。

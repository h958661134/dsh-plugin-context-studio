# v1.7：Git 分支式整理控制台

本文是已批准的控制台布局、卡片信息及「整链/到此节点/局部 → 预览 → 新会话草稿」流程的实现规格。主界面取代 [DESIGN 第 17 节](DESIGN.md#17-v16从整理结果到任务地图2026-11-16) 的三列任务地图，以 [第 18 节](DESIGN.md#18-v17git-分支式整理控制台) 为准。Git 分支只是阅读路径的视觉表达，不创建 Git 分支，不宣称 DSH 原生 fork、真实历史分叉或执行因果。

实现依据：`lib/client.js` 的 `ReportMap`、`consoleGraph`、`consoleMissing`、`reportDraftItems`、`launch` 与派生记录存取；报告字段和校验以 [REPORT-CONSOLE-CONTRACT](REPORT-CONSOLE-CONTRACT.md) 为准。新增报告模板为 3，存储版本仍为 1。浏览已有报告、选材及草稿预览不调用 LLM；只有另行确认的生成整理流程才使用模型。

## 1. 控制台布局

| 区域 | 当前行为 |
| --- | --- |
| 顶栏 | 报告标题、截至回答、AI 整理路径标识，以及「浏览与复用不调用模型」说明。 |
| 左侧导航 | 路径、待核对卡片、派生草稿三组。路径点击只切换浏览与高亮；派生记录限定当前 sessionId/jobId。 |
| 画布工具栏 | 当前路径标题、选用整条链、缩小/复位/放大。无路径时整链操作禁用。 |
| 中间画布 | 横向前缀树、未归入路径的独立卡片和派生草稿节点；可滚动及拖动空白处平移。点击卡片查看，复选框负责选材。 |
| 右侧浮层 | 在节点详情、原文核对、新 context 配置和派生快照之间切换；关闭按钮或 Escape 收起。 |
| 底部新起点 | 当前节点/原文数量、可移除的选材标签、附带引用原文开关、材料 token 估算和「派生新 context」。 |
| 范围折叠区 | overview、选入/省略/截短材料数及固定警告；未提供的内容不声称已分析。 |

桌面布局使用窄导航、可滚动画布和覆盖式详情浮层；画布按视口高度在320–506px间适配、浮层宽326px，并受可用宽度约束。路径实线表示 AI 整理顺序，派生草稿虚线表示选材来源；不是执行状态线。派生记录在左栏可查看，画布只画最近 3 份，避免持续拉长图。

画布平移使用 pointer capture 改变 scrollLeft/scrollTop，按钮、输入框等控件不触发拖动；复位恢复缩放与滚动原点。缩放叠加可用宽高适配，基础缩放最低0.8，优先保持卡片可读，超出范围使用画布内滚动。CSS 已有容器宽度 850px 和 580px 两级规则：更窄时导航改成横向条、底部换行、画布高度在300–430px间适配。900×800已验证外层无横向溢出；更小设备仍需单独验收。

## 2. 卡片信息与 AI 标注

| 字段 | 限制 | 显示与含义 |
| --- | --- | --- |
| title | ≤100 UTF-16 单元 | 短标题；卡片另显示 N 编号及类别。 |
| summary | 可选，≤180 | 画布优先显示 concise summary；缺失时仅在视图中用 body 作为摘要预览，不回写或补生成 summary。 |
| scope | 可选，≤120 | AI 给出的适用范围，详情可展开查看。 |
| caveat | 可选，≤160 | AI 给出的限制或待核对事项，详情中突出显示。 |
| state | 可选枚举或 null | 只作 AI 标注，不能显示为已验证事实。 |
| body / evidence | 沿用 v1.6 | 详情显示正文和有效原文引用；短卡片不是最终带走内容的全部。 |

文本超长按契约安全截断，不拆开 UTF-16 代理对；错误类型不强制转为文字。卡片下方优先显示「本次不带走」，否则按 caveat、scope、state 提示的顺序选择一行。标题与摘要在画布中限制行数，全文进入详情。来源数和 token 是提示，不是证据强度或事实评分。

state 的展示语义如下：

| 值 | UI 含义 |
| --- | --- |
| recorded | AI 摘录；材料中有记载，仍须核对原文。 |
| hypothesis | 待验证假设。 |
| conflict | 疑似冲突，尚未确认。 |
| superseded | 可能已被替代，尚未确认。 |
| null / 缺失 | 未提供状态；不根据标题、类别或原文位置补写 state。 |

缺少状态时的「AI 摘要」或 risk 类别的「待核对」只是通用界面提示。明显冲突或失效保持待核对措辞，不据此自动删材料。生成草稿使用 title/body，并携带已有 scope、caveat 和允许的状态说明，统一标为「AI整理建议（待核对）」；不是只复制画布上的 summary。

## 3. paths 与完整前缀实例树

报告接收规范化的 `paths: [{id, title, nodes: [cardId]}]`；只有模型显式提供且通过校验的路径才参与建树。最多检查前 8 条、每条 1–20 个不重复节点。原路径 ID 和原卡片 ID 的唯一性检查覆盖完整输入，包含超限或无效项；任何歧义节点使整条路径失效，不通过删节点修成另一条路径。

实例键为 `JSON.stringify(nodes.slice(0, index + 1))`。仅完整相同前缀共享实例；卡片身份与路径实例身份分离：

| 输入路径 | 必须保留的实例关系 |
| --- | --- |
| A→B→C、A→B→D | 共享 A 和 A→B，再分歧。 |
| A→B、A→B→C | B 既可为一条路径终点，又可为另一条的中间点。 |
| A→B→D→E、A→C→D→E | 分歧后的 D、E 都是不同实例，不能按卡片 ID 或直接父节点重新合并。 |
| A→B、C→D | 保留不同根，无需补共同根。 |
| A→B、B→A | 保留两条独立路径，不合成全局环。 |

跨路径同一卡片出现在不同前缀下时，保留路径并提示实例分离，不裁定真实流程。路径实线不要求 relations 存在对应边，也不创造新的 supports/depends_on。relations 及共同引用仍可在详情中核对。

没有 paths 的旧报告进入 free（自由选材）模式：卡片作为 `loose:<cardId>` 独立节点排布；有有效 relations 则显示 AI 关联长虚线，有共同有效引用则显示点线。没有这些数据就没有相应连线。不得从 category、标题、节点顺序或共有引用编造路径，不触发补生成；未被显式路径收录的卡片同样保留为独立节点。

## 4. 选择语义与缺项提示

浏览状态与选材状态分离：`state.path` 是当前浏览路径，`state.instance` 是当前查看实例；`state.cards` 是带走的卡片 ID，`state.instances` 记录选择发生时的完整前缀实例。切换路径、查看另一节点或核对原文，**不得随浏览路径改写 state.instances**。同一卡片的多个图中实例可以共享选中外观，草稿按卡片 ID 去重，但缺项判断和派生来源须保留所选实例的前缀。

| 操作 | 改变选择的范围 |
| --- | --- |
| 选用整条链 | 以当前路径 nodes 顺序替换节点选择，记住每个前缀实例；尊重「本次不带走」的排除项，重置单独原文选择及原文排除。 |
| 选用到这里 | 使用当前实例 trail，从该路径根到当前节点，包含当前节点；不扩选另一分歧的同名卡片。 |
| 局部勾选 | 只增减用户点击的卡片，并记录对应实例；不自动增加目标、相邻卡片、前置节点或依赖。 |
| 本次不带走 | 临时排除卡片并移出当前选择，可恢复；不改报告、原会话或项目文件。 |
| 清空选择 | 清除卡片、实例及单独原文选择；不删除报告和派生记录。 |

「可能缺少前置材料」根据已选实例的未选前缀节点，以及已选卡片明确 `depends_on` 的目标计算。它是阅读完整性的提示，不能提升为已证明依赖。切换浏览路径不会让局部选择突然继承另一条链的前置项。共享引用、supports/questions/addresses 不触发自动补选；用户可显式点「补选这些节点」，也可继续保持局部到最终预览。

「附带引用原文」默认开启，只附已选卡片在本报告中的有效引用；可关闭、逐项排除或单独选入原文。无摘要但有原文也能准备草稿。未选卡片的摘要不带走，但它与已选卡片共用的同一段原文可能仍被选入，界面明确解释这一点。

选择缓存按 `[sessionId, jobId]` 隔离，客户端模块内最多保留 6 份；切视图可恢复，整页重载不承诺保留未确认选择。这与下述 localStorage 派生 snapshot 是两种不同状态。

## 5. 来源对照与预览后只填草稿

点来源芯片先显示本次报告保存的片段、seq、字符范围及截短状态；可返回节点或选材配置，也可跳转到对应回答范围的原始记录。详情的「关联与对照」区分 AI 关系与实际共同引用，展示相关卡片和关系 evidence。引用存在只说明来自白名单，不证明 AI 判断成立。文本按不可信内容显示，不执行 HTML、命令或其中的指令。

流程固定为：

1. 从整链、到此节点或局部选材进入「派生新 context」，核对节点和原文，填写任务及目标项目。
2. 点「预览新会话」调用现有 compose，只拼选中材料，不生成模型回答；地图选材与旧 board 隔离。
3. 确认框显示完整草稿、选入/未选内容、可能缺项、目标项目和 token 估算。材料估算与包含来源说明、任务等内容的完整草稿估算可不同；均非供应商计费数。
4. 确认后调用 `uiWorkspace.startSession` 预填目标工作区的空白会话，默认 `whenDraftExists: 'append'` 保留已有草稿；用户可明确选 replace。**不发送、不 fork、不把整段历史隐式复制进去**。目标项目自身指令仍由 DSH 加载。

宿主没有预填能力时，地图流程仍先预览，确认后只复制草稿。取消不调用 startSession、不复制、不写 trace。来源会话已切换时旧确认失效，应返回重新预览。确认成功只代表草稿已预填或复制，不代表后续对话已产生。

## 6. 派生 snapshot

预填或复制成功后才保存派生记录，键为 `dsh-context-studio:context-drafts:v1`，仅在此浏览器的 localStorage 中。记录包含来源 jobId/sessionId、标题/时间、选中 cards/sources、路径与 instances、任务、目标、选材 items、当次完整 prompt，以及 `prefilled` 或 `copied` 结果。

保存时最多保留 **20 条**，整个序列化数组 `JSON.stringify(rows).length` 不超过 **500000 个 UTF-16 单元**，不是 500000 字节。先按新到旧保留，再淘汰最旧项直到满足容量；单份记录仍超限则拒绝保存并提示。存储不可用同样提示，但不撤销已在目标位置生成的草稿。

返回报告后左栏可见派生 snapshot，画布显示最近几份的来源标记；打开可看当时的完整草稿，并「恢复这份选材」。恢复保留 snapshot 的实例、节点、原文、任务和目标，关闭自动补附原文，避免悄悄加入新材料；再次派生仍须重新预览确认。

snapshot 是当时的草稿与来源记录，不是目标会话实时镜像、完整对话或真正的父子会话链；目标输入框后续编辑不会同步回来。它不记录可靠的目标会话 ID，不承诺原生分支导航，也不跨浏览器同步。清理浏览器数据或容量淘汰会丢失记录，界面不能称其为永久归档。

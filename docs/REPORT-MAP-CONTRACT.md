# 整理任务地图数据契约（v1.6 / templateVersion 2）

新生成的 `report` 保留 `title`、`overview`、`cards`、`branch`、`warnings`，增加 `relations: []`。卡片仍为 `{id, category, title, body, evidence}`；`id` 按保留卡片顺序生成 `card-1`、`card-2`，不透传模型 ID。类别仍限 `goal | decision | evidence | risk | next`。

模型提示要求 6–10 个短节点（材料不足可更少）、每卡唯一字符串 `id`，允许省略 `relations`。关系输入为 `{from: <卡片原id>, to: <卡片原id>, kind, evidence: [seq]}`；解析输出仅为：

```json
{"id":"relation-1","kind":"supports","from":"card-1","to":"card-2","evidence":[9]}
```

| kind | 方向含义（均为模型推测） |
| --- | --- |
| `supports` | from 支持 to |
| `questions` | from 质疑 to |
| `addresses` | from 回应或处理 to |
| `depends_on` | from 依赖 to |

- 端点只接受已保留卡片的唯一原 ID：非空白字符串，最长 100 个 UTF-16 单元，按原样精确匹配，不转换类型、去空格或截断。唯一性检查覆盖全部输入卡片，包括无效卡片和第 20 张以后的卡片。缺失、不支持或重复 ID 不影响卡片展示，但不能作为关系端点；不按标准化 ID、类别或顺序补连线。
- 非数组 `relations`、非对象关系、未知 kind、无效/缺失/重复原 ID 端点、自环、没有有效引用的关系均丢弃，固定警告为「模型返回了无效或不受支持的关系，已忽略。」同类警告去重，不回显原始坏值。省略字段或空数组不产生此警告。
- `evidence` 只检查前 8 项，只接受本次 `sources[].seq` 中的非负安全整数；去重、保持顺序，不接受数字字符串。关系至少保留一项，否则整条丢弃；不从卡片引用补齐。引用可独立于两端卡片引用，不代表语义已验证。无效引用沿用固定警告；超长关系引用提示「部分关系引用过多，仅展示前8个。」
- 最多检查前 20 张卡片、前 40 条关系，过滤后不向后补齐。关系超限提示「模型关系过多，仅检查前40条。」保留关系按输入顺序生成连续 `relation-n`；不信任模型提供的关系 ID，也不合并同端点关系。不同关系可具有相同端点，方向和 kind 按输入保留。
- 字段长度限制沿用：报告标题/卡片标题 100、overview 800、卡片 body 1500、branch.task 5000 个 UTF-16 单元；截断避免拆开代理对。原始输出总上限 100000。提示目标仍为 body ≤400 字、overview ≤180 字；这些目标不改变旧格式解析上限。

只要有保留关系，固定附加警告：「关系仅为模型根据所给片段提出的推测，不代表已证明的因果或依赖；请核对原文。」解析只验证结构、端点与来源范围，不验证因果、事实或依赖是否成立。客户端须将模型文字作为不可信文本显示，不能执行其中的 HTML、命令或指令；来源跳转仅使用已校验的 seq。

旧模型输出可没有卡片原 ID、没有关系；解析仍成功并返回 `relations: []`，不编造关联。已持久化的 v1 报告保持原样，可能缺少 `relations`，消费者按空数组处理，不迁移、不重新调用模型。新调用收据 `templateVersion: 2`，存储 `version: 1` 不变。API、模型路由、重试策略、调用确认及额度保护均不变。

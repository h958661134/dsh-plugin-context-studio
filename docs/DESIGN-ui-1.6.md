# Context Studio 1.6：任务地图与再使用设计

状态：2026-11-16 已实现并完成隔离浏览器验收；本地未发布。交互 / 视觉设计、关系契约和独立工程校验分工完成。本文记录最终实现，实测与未验证项见 [REVIEW-1.6](REVIEW-1.6.md)。

## 1. 从花过的 token 出发

用户已经为整理付出成本，首屏应该回答：这项工作现在知道什么、哪里需要核对、怎样继续。结果是一张可操作的任务地图，而不是让用户再读一遍长简报、再手动复制。

主路径：**已有结果 → 看图 → 核对节点与原文 → 选择带走的内容 → 预览完整草稿 → 新会话输入框**。这条路径不产生模型调用。只有创建新整理时，沿用预览范围和明确费用确认。

有运行中作业时先显示状态；否则优先打开最近一次成功报告，失败或取消通过提示入口查看，不遮住已经花 token 得到的结果。没有报告时提供看全局、排查问题、准备接手三个整理目的。新整理的预算配置折叠，费用确认不省略。

## 2. 页面层级

1. 宿主内的精简应用栏、会话选择与“任务地图 / 原始记录”。
2. 报告标题、简短概览、回答边界和纳入数量。模型与用量收进状态栏，“重新整理”位于“用量与状态”。
3. “看全局 / 找疑点 / 看下一步”和“选好接手材料”。
4. 左侧任务地图、右侧节点详情。
5. 独立的新会话起点区：所选节点、原文数量、材料估算、任务和目标项目。
6. 折叠的范围限制，以及以前保存的跨会话草稿。

初始没有选中节点或材料，详情区用三步指引说明操作。点节点只查看；复选框负责选材，避免用户边读边不知不觉改变下一次上下文。

## 3. 视觉与布局

采用白色主面、浅点阵画布、细边框与单一靛蓝强调色。类别用小图标、短标签和少量颜色区分，长正文留在详情。标题24px、节点标题13px、详情标题17px，缩放只作用于画布。

SVG 连线和 HTML 节点放在同一坐标层。逻辑画布宽896px；节点248×108，列间距52、行间距24。三列依次是目标/依据、结论/疑点、建议下一步。分列不是时间顺序，也不自动形成箭头。

容器宽度超过1050px时地图与280px详情并排。窄屏保留地图宽度，点节点后显示可关闭的详情抽屉；抽屉有独立滚动，关闭或在详情内按 Escape 返回。用户可以缩放、适应宽度或滚动较大的画布。最终在1440×900和900×800浏览器视口验收。

## 4. 两类关系分别呈现

| 类型 | 条件 | 呈现 | 事实边界 |
| --- | --- | --- | --- |
| AI 关系 | 模型明确返回，端点和引用通过校验 | 实线、方向箭头；聚焦时有支持/质疑/回应/依赖标签 | 模型提出的解释，需核对，不是已证实因果 |
| 共享引用 | 两张卡片引用相同的实际来源 seq | 虚线、无箭头 | 只证明共同引用，不证明互相支持或依赖 |

旧报告没有 relations 时只画共享引用，不猜关系、不迁移报告、不要求重新整理。新报告默认展示 AI 关系，点节点后补充与它有关的共享引用。最多画60条线，超过会提示；详情的关系清单仍可查看所有邻接关系。

同列关系从节点右侧绕行，跨越中间列的关系走上方轨道，避免穿过无关节点。箭头方向严格按 from→to，不能随视觉列位置反转。完整方向、关系类别和引用也以 HTML 列表呈现，不能只靠线条或颜色阅读。

模型仍只接受有界 JSON；最多20节点、40条显式关系，关系必须有本次来源。重复/歧义 ID、缺失端点、自环、不支持类型及无依据关系被拒绝。详见 [关系契约](REPORT-MAP-CONTRACT.md)。

## 5. 节点怎样变成可用内容

点击节点，详情显示正文、原文依据、相关节点。点引用在详情内显示保存的实际片段、字符区间和“带上这段原文”；进一步检查可跳到“原始记录”，保持报告的历史回答边界。

“本次不带走”使节点变淡并从当前选择排除。它仍在图中，可以恢复；不删除源日志、报告或 memory。

两种显式捷径：

- “选好接手材料”：选择目标、结论、疑点和下一步，默认附上引用原文。
- “围绕这个疑点准备新会话 / 从这个节点继续”：选择当前节点、目标与直接相连的 AI 节点，不因共享引用把所有邻居一起带走。

捷径会重新准备这次的节点选择和中性核对任务，并滚动到起点区；用户可以继续删选和改任务。它们尊重本次排除的节点。普通勾选不强制跳动页面。

## 6. 新会话起点与确认

起点区分别统计 AI 节点与原文；默认附带选中节点的引用，可整体关闭或逐段取消。材料估算只计选中正文，完整草稿预览还包括来源标识、标题与任务，因此数值会更高。

“预览新会话”调用现有 compose，只使用当前地图明确选择的材料，不混入历史跨会话草稿。AI 内容保留待核对标识、reportId、sessionId、有效引用；原文保留 seq、offset 和正文。图上的关系不导出为事实。

完整草稿确认框提供目标项目、全文和已有草稿追加/替换选项。确认后只调用宿主 startSession 预填；无此能力时确认后复制草稿。不会自动发送、修改指令或执行建议。切换来源会话会使未完成的旧预览和旧确认失效，迟到响应不能覆盖当前内容。

地图选择独立于旧 board。选择状态按 sessionId + job.id 缓存在当前客户端模块，最多6份：切换原始记录或暂时离开面板再返回可以恢复；完整刷新、重启或缓存淘汰会重置。报告本身仍持久化。旧 board 的保存、排序和历史草稿入口保留。

## 7. 安全和实现边界

纯 JavaScript、共享 React、SVG + HTML，无新图形依赖或 CDN。没有新增宿主接口：地图数据来自现有 organize-job，预览沿用 compose，最后使用已核对的 uiWorkspace.startSession。模型输出作为普通文字渲染。

地图只代表这份整理覆盖的材料；纳入、截短和遗漏数量可查看，不能说已经读完全文。模型关系有来源仅表示引用有效，不证明语义正确，也不揭示内部推理。已有 OpenCode 路由、取消、重复派发保护和安全错误分类继续沿用。

## 8. 本轮未实现的设计扩展

独立设计初稿提出过文字简报切换、图内搜索、多类型筛选、关系模式开关、手动拖动/平移、方向键空间导航和持久化选材。这些未纳入本轮，不作为已交付能力。当前只提供三种阅读过滤、显式缩放、HTML关系列表和独立临时选择。

后续优先：验证真实模型关系质量；文字阅读替代与搜索；节点人工修订、报告版本比较；选择持久化与新会话回链；减少密集连线交叉；补全焦点返回、读屏、深色、高DPI和原生桌面矩阵。

## P1-01：没有请求截止时间；脉络阻塞同时阻塞会话导航

**证据**：`lib/client.js:29–49` 的 GET/POST 只有 fetch 和 JSON 解析，没有超时或 AbortSignal；`746–756` 在 graph 返回前保持 null；`397` 将 null 显示为「读取脉络中…」。`782–783,1045–1046` 的排查会话列表也只从完整 graph 提取，不能先列出会话再独立检查。`618–626` 的 Inspector 有失效标志，但没有中止请求或截止时间。

**触发与复现**：令 `/graph` 的 fetch 永不完成；挂载页面后推进模拟任务，graph 始终为 null，没有注册请求截止计时器。点击「重新读取」后未结束的 graph 请求从 1 个变为 2 个，旧请求仍在运行。`/inspect` 或响应体解析长期不结束时也有同类问题。

**影响**：持续显示加载，用户无法区分慢、挂起、断连；会话导航和脉络一起不可用。刷新可能增加后台工作。服务端 `lib/graph.js:385,417,430–449` 等待列表、标题和所有池任务，单次 `readSession` 永不返回足以让整张图不返回；这是代码可行路径，并未证明用户当时就是该服务挂起。

**建议**：为查询及响应体解析设置明确截止时间，切项目/卸载时取消，错误态提供重试与保留已有内容的选项；会话列表与完整脉络读取解耦。服务端单会话失败或超时应形成可见的部分结果。写操作超时应提示「结果未知，核对操作记录」，不能自动重放写入。

**回归**：永不完成的 fetch、永不完成的 `response.json()`、一次会话读取挂起、失败后重试成功；断言限定时间内离开无限加载，旧请求被中止或结果被忽略，重试不会自动重复写操作。

## P1-02：持久化失败完全静默，重开后新草稿丢失

**证据**：`lib/client.js:54–55` 捕获 localStorage 写异常后直接忽略；`757–758` 把草稿与任务保存都交给该函数，界面没有保存状态。README `204` 直接描述所选片段与任务保存在本机浏览器。

**触发与复现**：初始存储为 OLD，模拟 `localStorage.setItem` 抛出配额异常；把草稿改为 NEW。内存显示 NEW，没有 toast 或未保存提示；重新挂载读取的仍是 OLD。拒绝存储、空间耗尽等都可触发；未实测用户浏览器配额。

**影响**：用户以为编辑已保存，退出面板或重载后才发现缺失。若原存储为空，可能丢失整份新草稿；任务偏好也受影响。

**建议**：返回保存结果并持续显示「尚未保存」；保留内存内容，提供导出/复制或缩减后重试，不在保存失败时清空原存储。读取 storage 失败也应与首次空草稿区分。

**回归**：配额异常、拒绝存储、恢复可写三种场景；断言失败时有持续提示、内存仍可导出、恢复后保存成功，重开内容一致。

## P1-03：取消拖拽后残留索引可插入 undefined，导致草稿组件崩溃

**证据**：`lib/client.js:293,301–308,321` 通过 `drag.current` 记住数组索引，只在 drop 中清除，没有 `onDragEnd`；`312` 接受任意 dragover；`303` 仅检查下界，没有检查索引仍在数组内，也没有验证本次拖拽属于该草稿。`319` 和 `781` 随后直接读取 item.key。

**触发与复现**：

1. 草稿有 A、B，开始拖 B，然后在草稿外取消。
2. 点击 × 移除 B，数组剩 A，残留索引仍为 1。
3. 从别处拖入普通文本，`text/x-csx-piece` 为空，drop 使用残留索引。
4. `splice(1,1)[0]` 得到 undefined，生成 `[A, undefined]`；下一次 Board 渲染读取 key 抛错。

另一个探针确认：即使不移除条目，取消拖拽后的无关外部 drop 也会错误重排草稿。

**影响**：无需坏服务端数据即可使插件渲染失败；实际显示空白还是宿主错误页取决于宿主错误边界。不能据此断言宿主整窗崩溃或已经丢失源文件。

**建议**：dragend 无条件清理；使用稳定条目 ID 和本次拖拽标记；验证拖拽来源、索引范围及 moved 是否存在，再更新状态；忽略外部普通文本拖入。增加组件级错误恢复，避免一个坏条目拖垮整个页面。

**回归**：拖拽取消→删除原条目→外部文本 drop；断言 items 不变、不含 undefined、不抛错。另覆盖取消后重排、拖拽中数组改变、正常跨位置排序。

## P2-04：项目切换存在两个跨项目数据污染窗口

**证据 A**：`lib/client.js:755` 切项目时启动 reloadPieces，但不清除旧 data；`780,1075–1079` 继续渲染旧素材。`797–799` 将素材来源与 origin 设置为当前选择的项目，没有使用素材所属项目。

**复现 A**：A 的素材加载完成后切换到 B，并挂起 B 的素材请求。A 的卡片仍可勾选；探针确认加入草稿的文本是 A 内容，`origin` 与 `from` 却变为 B / AGENTS.md。

**证据 B**：`934–938` 分叉完成后 `setTimeout(reloadGraph,600)` 捕获原项目；`746–751` 只比较计数 ticket，没有校验返回所属项目是否仍为当前项目。`824–829` 的 act 完成回调也捕获原 render 的 reload 函数。

**复现 B**：在 A 分叉，成功后切 B；B graph 返回成功，再触发 600ms 计时器并返回 A graph。探针确认左侧选中 B，脉络数据已被 A 覆盖。旧回调启动得更晚，因此会获得更大的 ticket，现有防乱序机制挡不住。

**影响**：展示、来源标签与当前项目不一致，可能将不期望的素材写入目标项目。后端 remove/archive 有重新定位和归属校验（`lib/host.js:115–134`），所以本项**不声称已经证实跨项目误删文件**。

**建议**：数据携带 projectId，提交响应前同时校验项目和请求代次；切项目时隐藏/禁用不属于当前项目的数据。延迟刷新读取最新项目，或仅刷新对应项目缓存；清理过期分叉计时器。来源从数据身份获取。

**回归**：A→B 慢请求期间不能把 A 卡片标成 B；A 操作结束/分叉计时器晚于 B 返回时，B 仍显示 B 的数据。

## P2-05：复制会导出旧内容或错误文本，降级启动也绕过刚生成的新草稿

**证据**：`lib/client.js:768–776` 预览防抖 250ms，变化时不使旧预览失效；失败时把「预览失败：…」放进 `preview.text`。`982–986` 直接复制该字段。`954–958` 已取得 fresh compose，缺少 startSession 时却调用复制旧 preview 的 copy()，并先声称「已复制」。

**触发与复现**：已获得 OLD 预览后把草稿改成 NEW，立即点复制，剪贴板模拟器得到 OLD。compose 拒绝后点复制，得到错误提示文本。缺少 startSession 的环境下，fresh compose 返回 NEW，启动降级仍复制 OLD。

**影响**：用户携带或粘贴的内容与当前选择不一致，可能漏掉刚补充的关键约束。首次预览尚未返回时 copy 直接 return，按钮看起来无响应。

**建议**：预览状态区分 pending/success/error，并关联草稿版本；复制时使用当前版本的成功结果，等待或明确禁用旧结果。降级启动复制 `fresh.text`，等待剪贴板成功后才提示成功。受限剪贴板环境保留可选择的完整文本作为出口。

**回归**：编辑后立刻复制、首次预览 pending、compose 失败、startSession 缺失、clipboard 拒绝；断言不会复制旧内容/错误文本或虚报成功。

## P2-06：localStorage 只校验 JSON 语法，坏形状会形成持续渲染失败

**证据**：`lib/client.js:51–52,708` 接受任意合法 JSON；`781` 调用 board.forEach 并读取 b.key，`Board:316–329` 也信任元素形状。

**触发与复现**：在隔离模拟存储中将 board 置为 `{}` 或 `[null]`，每次挂载分别在 forEach 或 key 处抛错。需要先有损坏或不兼容的存储值，本次未观察到用户实际存储存在此情况。

**影响**：重开页面继续失败，界面没有只重置损坏草稿或导出原值的入口；通常需外部清理存储才能恢复。

**建议**：加载时校验版本、数组、元素字段和合理尺寸；恢复有效条目，保留原始坏数据供导出，不应自动永久删除用户草稿。初始读取改为惰性初始化，避免每次输入/选中都重新解析整份存储。

**回归**：`{}`、`[null]`、缺字段元素、旧版本结构、非法 JSON；断言有可操作的恢复界面，不在 render 中抛错。

## P2-07：Inspector 无条件使用 findLast，缺少该能力的桌面内核会在返回数据后崩溃

**证据**：`lib/client.js:640` 调用 `filtered.findLast`，未降级或检测。`package.json` 的 Node ≥22 限制不等于宿主浏览器的能力保证；README `44` 没有说明 WebView/浏览器最低能力。

**触发与复现**：仅在隔离 VM 中删除 `Array.prototype.findLast`，加载 Inspector 并完成一个空上下文响应，渲染抛出 `findLast is not a function`。正常首次载入 selected 为空时会执行到该表达式，即使 filtered 为空也会调用。

**影响**：在缺少此 API 的内核上，点击会话后数据读取成功，却无法显示检查结果。这是条件性兼容问题，**未检测用户的实际内核，也未证明当前受支持 DSH 桌面版本缺少该 API**。

**建议**：使用反向遍历辅助函数或显式兼容层；明确受支持桌面内核，并为缺少能力提供可见错误而非 render 抛错。其他较新语法/API（`?.`、`??`、flatMap）及 CSS container queries/color-mix 也应纳入实际版本矩阵；本次未做这些能力的真实内核验证。

**回归**：缺少 findLast 的环境仍能默认选择最后一条用户要求；空记录、只有工具记录、有明确 selected 的情况都能渲染。另在产品实际支持的最低桌面内核跑 smoke test。

## P2-08：摘录请求无身份校验，关闭后重开、后选会话被先选会话覆盖

**证据**：`lib/client.js:884–888` 无 request token/取消标记；成功与失败回调都直接设置 snippets。`755` 的切项目清空和 `1009` 的关闭都不能使已发请求失效。

**触发与复现**：打开 A 摘录，挂起请求，点击关闭，再返回 A 响应；探针确认已关闭面板重新出现。A→B 两个请求按 B→A 返回时，同一逻辑会把 B 选择覆盖为 A。

**影响**：用户看到与最后一次点击不一致的会话，关闭或切项目不能稳定结束操作；有误选摘录的风险。

**建议**：每次打开、关闭、换项目都更新请求代次，并校验 sessionId；取消旧请求。复用 Inspector 已有的失效响应屏蔽思路，但同时加入超时。

**回归**：A/B 逆序返回、关闭后返回、换项目后返回、旧请求失败晚于新请求成功；断言保持最后一次用户意图。

## P2-09：确认框 busy 状态跨操作残留，旧操作可以关闭新确认框

**证据**：`lib/client.js:225–239` 的 busy 属于常驻 Dialog；处理中仍可取消或点击遮罩关闭；后续新 dialog 沿用同一状态。旧 promise 成功后一律执行 props.onClose，没有核对当前 dialog 身份。`231` 在 Promise.resolve 之前直接求值 `d.onConfirm()`，同步异常也不在失败回调保护内。

**触发与复现**：确认 A 后挂起，点击取消，打开 B。探针确认 B 显示禁用的「处理中…」；A 完成后又调用关闭回调，关闭 B。另将 onConfirm 模拟为同步抛错，busy 仍为 true。

**影响**：新操作看起来无响应；「取消」容易被理解为停止写入，实际 A 仍可能完成；旧操作关闭正在审阅的新确认框。这里没有证实未经确认就执行 B。

**建议**：每次 dialog 使用独立 ID/状态，完成回调只更新所属 dialog；把同步调用放入 try/finally 或 promise 回调。明确处理中「关闭」不等于取消后台操作；若不支持取消，应禁用取消或改变文案，并仍可在操作记录核对结果。

**回归**：A pending→关闭→打开 B→A resolve/reject；B 不继承 busy、不被 A 关闭；同步抛错也能恢复并提示错误。

## P2-10：长便签/素材被静默截断，现有测试只确认截断长度

**证据**：`lib/client.js:813–820,1098` 未限制便签/任务输入；`lib/compose.js:23–24,42` 每项裁至 20,000 字符；`lib/host.js:113` 也裁任务。compose 返回值没有每项截断信息。README `95` 的明确提示适用于 Inspector 展示，但无法覆盖其他草稿入口。

**触发与复现**：加入 `"x".repeat(20000) + "TAIL-MUST-SURVIVE"` 的便签，经 sanitizeItems→compose 后尾部标记消失，count 仍为 1、skipped 为 0，没有 clipped 信息。`tests/compose.test.mjs:52–58` 正在断言裁剪长度，没有验证用户能知晓遗漏。

**影响**：预填、复制或写入指令都可能缺少尾部关键要求，而草稿卡片仍代表原始内容；源文本不一定被删除，但输出已经丢信息。200 块上限、512KiB 请求体上限（`lib/guard.js:9`）也缺少客户端预检，大草稿可能整体失败。

**建议**：保留服务端防护，但超限应拒绝并指出条目，或返回明确截断元数据让用户确认；客户端展示实际长度/请求限制。避免仅因 token 预算未超就暗示所有文本会完整输出。

**回归**：19,999/20,000/20,001 字符、末尾唯一标记、超长任务、201 项、超请求体大小；断言有明确错误/确认且不会静默遗漏。

## 交互不足与建议补充

这些项目主要来自静态检查，未作为真实浏览器复现结论：

- **会话打开缺少失败反馈**：`284,609,651` 的 openSession 调用没有等待或错误处理，能力检查也不一致。模拟缺少方法、抛错、拒绝 promise 时应显示可理解的错误；异步导航可提供短暂进行中状态。
- **键盘无法完成部分主要操作**：脉络行、记忆列、链标题使用带 onClick 的 div（`460–463,499–501,516`），缺少原生按钮语义/键盘激活；草稿排序仅拖拽。增加键盘选择、上下移动和可读名称。
- **确认框焦点管理缺失**：虽有 role=dialog/aria-modal，但没有可访问名称关联、初始焦点、Tab 限制、Escape 和关闭后焦点恢复（`225–239`）。应以真实 React DOM 验证。
- **清空不能撤销**：`1086` 立即清空并保存，没有确认或撤销；容易丢掉花时间整理的草稿。建议短期可撤销，而不是每次选取都增加确认。
- **目标项目会被添加动作改写**：`793,913–914` 自动切换目标；跨会话收集时可能覆盖用户先前明确选择的目标。建议只在尚未选择目标时自动填入，改动时给可见反馈。
- **写入预览失败无提示**：`856–858` 忽略错误，预览尚未成功时仍能确认写入。建议区分正在预览/预览失败，并在可核对目标和内容后开放确认。
- **窄屏与缩放尚未验收**：存在 container queries 和新 CSS 色彩函数，但本次没有视觉渲染。应覆盖草稿展开/收起、长会话标题、密集矩阵、窗口缩放和系统缩放，不把静态 CSS 阅读当成布局通过。

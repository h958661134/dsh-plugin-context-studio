# v1.5 会话整理：设计与客户端分工

## 面向用户的结构

默认进入“会话整理”，原有流转图保留为“原始记录”。两者共享当前会话选择、手动选择保护、原文来源和分支草稿。首次进入只解释整理能得到什么，并提供“预览整理范围”；加载页面、切换会话和刷新均不得自动调用模型。

整理页按四个阶段呈现，避免把配置、原文与结果同时铺满：

1. **引导 / 已有报告。** 简短介绍“目标、已确认、证据、待核对、建议下一步”。优先恢复已有作业或报告；已有报告说明生成范围和时间。
2. **调用前预览。** 明确展示将发送的会话范围、取样和省略量、估算输入 tokens、输出上限、provider/model，内容明细可展开核对。预览本身不调用模型。只有“确认消耗 tokens 并整理”才提交启动请求。
3. **正在整理。** 显示作业状态，轮询采用单次完成后再调度，不并行叠加请求。可取消；页面刷新可以恢复已有状态。启动超时显示“结果未知，先查询状态”，绝不自动重新启动。
4. **可读结果。** 用五类简短卡片组织目标、已确认、证据、待核对、建议下一步。证据可打开原文；建议只有“加入分支草稿”动作，不发消息、不自动写入记忆。内容来自模型整理，仍需要用户核对证据。

## 视觉层次

沿用低饱和蓝绿与中性背景，顶栏只增加两个明确模式按钮。初始页突出一个主操作，不展示大图和密集配置。预览阶段以摘要数值和发送目标为主，原文内容在折叠区。结果以一段总体摘要和五类信息分组，待核对项使用柔和警示色，建议以行动句呈现。分支草稿保持在侧栏，可从报告建议或原文片段累积内容。

完成且已有报告后，作业状态收成紧凑条：完成、模型、输入/输出用量摘要和“重新整理（先预览）”。收费提示、缓存/推理用量明细、查询状态放入默认折叠的“用量与状态”，让报告标题和简报卡片先进入视野。报告保存警告仍直接显示；运行中、失败、取消、中断、状态读取失败或后台仍占位时保留详细状态和操作出口。窄屏状态条可换行，不裁掉按钮。

## 安全与可靠性

- 模型接口按主代理冻结契约接入：模型目录与已有历史为只读 GET；预览、启动、取消分别调用各自接口。不猜测 provider 配置，不读取或填入密钥。
- 预览与确认必须对应同一个会话、回答边界及同一份输入预览；切换会话或回答边界使待确认预览失效。旧确认回调不能启动新边界下的整理。
- 用户确认前不启动模型；启动请求不自动重放。取消是停止作业请求，不承诺已经消耗的 tokens 可返还。
- 会话切换、卸载、重新预览会取消客户端读取；响应须匹配会话和请求身份，迟到结果不能覆盖新会话。
- 状态读取失败可以重试读取，不能变成再次启动。刷新优先恢复服务端已有报告/作业。
- 采用建议只加入现有分支草稿，并记录报告及证据来源；启动新会话继续沿用现有确认与只预填流程。

## 本轮验证计划

保留原始记录模式全部可靠性回归。新增可控异步测试覆盖零自动模型调用、预览确认、会话切换失效、防重复启动、启动超时、取消与轮询、刷新恢复、证据回原文、建议仅加入草稿。只使用假服务或本地函数契约测试，不调用真实模型、密钥或浏览器。

## 已实现的协议行为

- 初次打开仅请求 `/organize-models` 与 `/organize-history`；恢复作业使用 `/organize-job`。默认整理最新回答，预览请求省略 `answer`。缺模型时引导去 DSH 模型设置，不增加密钥输入框。
- 在“原始记录”选定回答后，点击“整理到这一步”回到整理页。父界面保存会话与回答序号，页面明确显示“整理范围：截至回答 #N”，预览请求带上 `answer:N`。入口仅切换视图，不自动预览或调用模型；已有较新报告也不能遮住这次重新预览的入口。
- “改为最新回答”保持当前会话，取消在途预览并清除待确认 Plan，后续预览省略 `answer`。边界纳入表单身份和响应校验，迟到响应或返回了错误回答边界的 Plan 均不可确认。切换其他会话不沿用旧会话的回答序号，正在运行的模型作业不会因改变查看范围而被擅自取消。
- `/organize-preview` 的 Plan 展示供应商/模型、截至回答、输入估算、输出上限、纳入/总量、截短/省略/排除系统记录、完整 system/input 快照。输入变更或会话切换取消预览，过期或来源不匹配的 Plan 不能确认。
- 只有明确点击“确认消耗 tokens 并整理”才提交 `{planId,confirmed:true}`。客户端在发起前锁定已消费的 planId，快速双击不重复启动。启动超时或断网后按同一 planId 查询作业，刷新和状态重试不会自动再次启动或重新预览。
- 作业轮询约一秒，前一请求完成才调度下一次；读取失败停止自动轮询并提供查询按钮。会话切换和卸载取消客户端读取，不擅自取消服务端模型调用。
- 取消请求独立执行；`cancelled` 但 `active=true` 时继续查询并阻止新整理，明确后台尚未释放、已消耗 tokens 不能返还。迟到的旧 running 响应不能覆盖较新的终态。
- 有 Usage 才显示供应商实际用量；总输入包含未缓存输入、cacheReadTokens 和 cacheWriteTokens。无 Usage 明确提示用量未返回、费用可能已经产生，不展示虚构金额。
- 报告五类实际名称为“目标与约束 / 已有结论 / 关键证据 / 待核对 / 建议下一步”。全部标注“AI 整理 · 需核对”，不把已有结论当成模型认证事实，不把风险描述为已确定根因。
- “原文 #seq”切换到原始 Inspector，使用报告 Job 的 answer 与来源 seq，自动打开对应历史边界的分页原文；保持一次性跳转，不夺走后续手动选择。
- AI 文字以 note 加入原有分支草稿，正文和来源显式写“AI整理建议（待核对）”、报告 ID、会话 ID。推荐任务作为独立便签，不覆盖现有 task。采用原文是另一项操作，保留 body 类型与真实 offset；同一报告建议及同一来源范围均去重。
- 当前会话跟随、手选优先、存储恢复、原始信息查询、现有草稿确认与只预填流程保留。切换模式不会触发模型生成。

## 验证结果与交接

客户端共有 **54 项测试通过**：原有 37 项回归保留，新增加 17 项可控异步整理测试。执行命令：`node --test tests/client.test.mjs tests/client-modules.test.mjs tests/client-organize.test.mjs`；`node --check lib/client.js` 通过。

新测试使用假 fetch、可控 Promise 和计时器，覆盖初次零模型启动、快照预览确认、防双击、修改和过期失效、会话切换、防迟到、启动超时、非重叠轮询、取消后占位、状态终态恢复、五类报告、缓存计费量、建议/原文分开采用、报告原文跳转、无模型及错误来源的预览。原有测试只调整父界面的默认模式选择断言，不删除分页、取消、来源、启动确认等关键场景。

收尾新增两项回归覆盖“原始记录 → 指定回答整理 → 改为最新 → 重新预览”、跨会话边界隔离、边界切换中止请求、迟到预览/错误边界/旧确认回调拒绝。已有报告恢复测试增加紧凑状态条、默认折叠明细与重新整理入口断言；失败、取消、中断状态仍验证详细出口。参考主代理提供的 `docs/images/organize-report.jpg` 调整完成态布局，更新后的真实屏幕效果由主代理继续验收。

本分工未调用真实模型、读取密钥、操作浏览器或运行环境；4001 的模型目录、预览和离线 QA 适配器验收由主代理负责。客户端测试不能证明真实模型整理质量、供应商收费金额或桌面最终布局。未修改后端、README，也未创建提交。

## 仍需改进的产品与工程不足

1. **大规模历史浏览**：目前最多 300 个目录项、单项目脉络默认 50 个顶层会话；需要分页、增量索引、进度和精确定位慢源。图仍是有界全量计算，尚非可中断后台索引。
2. **原生桌面兼容矩阵**：目前真实 UI 测试是隔离网页；没有完整的 Electron 各版、最低内核、高 DPI、缩放与超窄窗口自动化验收。VM 的 hooks 模拟不能代替真实 React DOM。
3. **外部并发写入**：协作锁不能控制编辑器或其他不遵守锁的插件。最终检查至覆盖窗口、路径别名/junction、ACL/mode 保留仍需专项方案和测试。
4. **恢复体验与磁盘留存**：崩溃锁、冲突恢复需要人工核对；缺少恢复向导、备份容量展示/清理。完成记录保留 200 条、准备/冲突另保留；UI 只显示前 30 条，不足以管理大量恢复记录。
5. **网络丢响应幂等**：没有跨 HTTP 请求的用户操作 ID。写操作超时必须先核对记录，不会自动重放，但不能自动识别用户重复点击是否故意。
6. **无障碍**：脉络部分 div 点击区域、纯拖拽排序欠缺键盘操作；确认框尚缺焦点圈定、Escape 和焦点恢复。
7. **草稿工作流**：清空缺少撤销；写入预览失败仍需要更强反馈与确认禁用；原会话打开失败反馈和目标项目自动选择需要进一步统一。
8. **诊断解释能力**：位置重建不是最终供应商请求，也不能自动证明错误原因；尚无相邻请求文本 diff、人工指令冲突标注、附件完整投影及精确 tokenizer。
9. **存储损坏边界**：草稿原值可导出恢复；偏好旧版本迁移、多个窗口同时编辑草稿、长期 localStorage 配额与冲突同步仍需专门设计。
10. **测试和发布**：本轮已建立客户端生命周期测试，仍缺真实桌面 UI CI、长时性能基准、最低 DSH 版本矩阵。发布前必须复测 README 的默认入口、截图与安装升级步骤。

## 安全复核

- 接口增加真实 peer 回环检查和协议在内的 Origin 比较。Host 白名单不再等同远端客户端授权。未测试远程代理部署，不将此插件宣称为远程服务。
- 不读取、输入或发送 API key；隔离浏览历史数据验证，无模型发送。没有修改 3999、Dot 工程或工作流调研工程。
- 返回内容不包含完整请求头、原始流与隐藏推理；可见原文和工具参数本身仍可能包含用户写入的敏感文本，不是通用脱敏器。
- `GET journal` 可能核对并落盘操作恢复状态，但不会重放文件或会话业务动作；其他诊断读取不改变源会话。

独立代理对加载修复再发现三处缺口，均追加处理：

- 共享池被后台长期挂起占满：保留交互名额、元数据独立池、服务变化重建池；`reads.test.mjs` 覆盖。

- 超时/权限错误被当文件删除：只有 ENOENT 为 missing，其他错误为 `exists:null/readState:unknown`，版本为 null；UI 显示未知，且有客户端回归。

最终宿主重启后的隔离接口实测：sessions 约 104ms、graph 约 151ms、journal 约 32ms。图返回 partial=true，原因是全局目录没有核对到某些项目技能的当前版本，界面提示未知；不是读取失败冒充删除。数字仅是本机演示数据单次观测，不能用作规模性能保证。最后通过 1440×900 尺寸检查并保存完整真实截图，随后恢复浏览器默认尺寸。

文件 I/O 剩余限制：单次图扫描最多 4 项尚未结束的文件 I/O，超时停止后续调度；stat/readdir 本身无法取消。该限制按扫描计，尚未实现跨请求全局文件 I/O 去重；频繁重试永久挂起磁盘路径仍需治理。

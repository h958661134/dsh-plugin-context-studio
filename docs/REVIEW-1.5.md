# v1.5 会话整理：工程验收

日期：2026-11-16。新增主动确认的模型整理，保留原始记录。客户端设计/实现与独立后端反例由两位子代理分工完成，主代理集成、复核与隔离宿主验收；不是人工设计团队认证，不声称穷尽全部缺陷。

## 已修复与确认

- 确认前不生成；预览给出实际 system/input、模型、估算预算和覆盖范围。模型目录可联网，但不是生成调用。
- 同计划派发前先持久化唯一凭据；25次并发 start 只产生一次 fake prepare/stream。取消、失败和重启不自动重放。
- 独立反例发现写凭据期间停止插件仍会继续派发，已增加落盘后的停止与身份核对；保留取消凭据，不删除再重做。
- 真实4001发现 Cordis 服务追踪代理每次不同，模型目录被误判为更换服务。核对 original symbol 后仅按底层身份比较，方法仍经过代理。会话读取去重、限流与原文缓存同样修复。
- 终态必须等最终持久化结果明确后才公开，保存失败的提示能随终态一起到达 UI；结果可留在内存供复制。
- 流终态不可被后续 stop 覆盖；工具请求不执行，异常格式不自动重试。供应商带 HTTP status 的原始错误也不回显。
- 五类简报明确 AI 整理属性，引用编号只能来自本次快照。建议便签与历史原文分别选择，不自动覆盖新任务。

## 已知不足

1. 未验收真实模型整理质量；JSON输出、推理占用、供应商收费和中止行为可能不同。固定演示结果只能证明集成路径。
2. 预算选材有损：最多80条、每条最多8,000字符；可能遗漏关键旧内容。覆盖数量不能证明语义充分，需核对实际发送文本。
3. 当前整理到选定回答为止，最新待回复输入可能未包含；不是实时自动滚动简报。
4. `readSession`仍先读完整日志；结构保护、文字预算和小响应不能约束这一步全部成本。
5. 引用存在不代表陈述正确，推荐不是内部根因证明。模型没有执行器，但用户仍需判断建议内容。
6. 同实例只允许一个底层调用；未实现跨进程全局限流。第三方适配器或中间件内部重试不受插件控制。
7. 报告包含本次历史片段，存于本机，无额外加密；未实现报告删除/导出管理与保留期限。只列最近10份，不自动删除更早文件。
8. 简报人工修订、版本对比、逐字差异与原生分支关系仍未实现。新分支是精选草稿，目标项目指令仍会加载。
9. 原生桌面窗口、高 DPI 和完整无障碍矩阵仍待验收，隔离网页通过不能代替这些结果。

## 1. 问题

用 DSH 久了，一个项目会慢慢攒下很多「给 agent 看的东西」：`AGENTS.md` 里一条条约定、`.agents/skills` 里的技能、几十个会话的历史。问题有三个：

1. **看不见、删不掉**：哪些约定已经过时（指向早就删掉的目录、和全局指令重复、半年没人动过）？现在只能打开文件逐行看，删错了也没有后悔药。
2. **复用难**：B 项目想要 A 项目「部署那一节」或「某次排查的结论」，只能手动复制粘贴，来源也丢了。
3. **开工慢**：开一个新会话前，要把「这次需要的约定 + 相关会话 + 关键文件」拼成一段起始上下文，全靠手工，也不知道占了多少 token。

拼图台把这些都做成一块可视化的画板：**按项目看素材 → 标出可疑的 → 一键移除（可撤销）→ 跨项目挑一块拼过去 → 拼成起始上下文 → 开新会话**。

## 2. 核心理念

- **素材即拼图块**：DSH 里一切「会进入模型上下文」的东西，都拆成带来源、新旧、token 的小块。
- **看见先于动手**：插件主动标出「疑似过时」，但从不自动删。
- **一切写入可回滚**：任何改动先备份、记日志、可撤销；冲突时宁可拒绝也不覆盖用户的新改动。
- **拼好的东西交给用户发出**：新会话只预填草稿，由用户自己按发送。插件不替用户调用模型。
- **只用 DSH 原生机制**：指令文件仍由 DSH 的 `agent-instructions` 加载，会话引用仍走 DSH 的 `dsh-session:` 提及，插件不自建一套注入通道。

## 3. 素材盘点（以源码为准）

DSH 本身**没有**名为 memory 的一等存储（全仓 `memories` / `MEMORY.md` 搜不到）。和「memory」对应的、真正会进入模型上下文的东西如下：

| 素材 | 在哪 | 谁加载 / 怎么进上下文 | 源码出处 | v1.0 |
|---|---|---|---|---|
| **全局指令** | `$DSH_HOME/AGENTS.md`、`$DSH_AGENTS_HOME`（默认 `~/.agents`）`/AGENTS.md` | `dsh-agent-instructions` 首次请求时作为基线消息注入 | `packages/context/agent-instructions/README.zh.md`「agent 获得的内容」 | 看 / 移除 / 拼接 |
| **项目指令** | 项目根（最近的含 `.git` 的祖先）到会话 cwd 每一级目录下的 `AGENTS.md`、`CLAUDE.md`、`AGENTS.local.md`、`CLAUDE.local.md` | 同上，从宽到窄 | 同上「配置」表 | 看 / 移除 / 拼接 / 写入 |
| **子目录指令** | 工作区下更深目录里的同名文件 | agent 用 read/write/edit 触达该目录后增量注入 | 同上「主要流程」 | 看 / 移除 / 拼接 |
| **技能** | `<root>/.dsh/skills`、`<root>/.agents/skills`、`$DSH_HOME/skills`、`<agentsHome>/skills`；`<name>/SKILL.md` 或 `<name>.md` | `dsh-skill-filesystem` 扫描、按需加载正文 | `packages/skill/skill-filesystem/README.zh.md`「根目录与优先级」 | 看 / 拼接（引用） |
| **会话** | 会话日志；工作区的 `sessionIds` | `ctx.sessionQuery.listSessions / readTitleSnapshots / filterEvents`；引用时用 `@[标题](dsh-session:<base64url(JSON(id))>)`，由 `dsh-session-reference` 展开为有界快照 | `packages/session-query/session-query/src/index.ts`；`packages/context/session-reference/src/uri.ts`；`packages/bundle/web-app/cordis.patch.yml` 默认挂载 session-reference | 看 / 归档（可撤销）/ 引用 |
| **会话片段** | 会话里的 `user/message`、`assistant/message` | 同上 `filterEvents(id, [{kind:'type',values:[...]}])` | `packages/core/session/src/types.ts` `SessionEventMap` | 看 / 摘入拼盘 |
| **项目文件** | 工作区内任意文件 | `@path` 提及（`dsh-file-reference`），模型需要时自己去读 | `packages/context/file-reference/README.zh.md`「mention 语法」 | 以 `@path` 拼入 |
| **Dot 记忆**（第三方） | `$DSH_HOME/dot/state.json` 的 `memories` | 由 dsh-plugin-dot 自己注入 | dsh-plugin-dot | 只读查看 / 拼入 |
| 系统提示片段（persona、time-context 等） | preset 配置 | 预设自身 | `packages/preset/persona` | 不做（见第 7 节） |

宿主侧会用到的服务（都在源码里确认过签名）：

- `ctx.workspaceRegistry.list()` → `Workspace{ id, path, title, sessionIds }`；`archiveSession(id)` / `unarchiveSession(id)` / `archivedSessionIds`（`packages/workspace/workspace/src/index.ts`）。
- `ctx.sessionQuery.listSessions()` → `SessionRecord{ header{ id, createdAt, cwd, parentSession, origin, agentPreset } }`；`readTitleSnapshots(ids)`；`filterEvents(id, filters)` → `{ seq, type, time, text }[]`。
- `ctx.webServer.register({ kind:'exact', path, handler })`、`webServer.getOrigin()`（参照 Dot 的用法）。

浏览器侧：

- `ctx.uiWorkspace.startSession(workspaceId, { prompt, whenDraftExists })`：打开工作区的空白会话并预填草稿（`packages/client/ui-workspace/src/client/navigation.ts`，`DraftInitializationOptions` 在 `ui-conversation/src/client/contract/input.ts`）。安装版 `app.asar` 里能搜到 `whenDraftExists`。
- `ctx.slots.inject/register('main' | 'sidebar.panellist')`、`ctx.layout.selectPanel`（参照 Dot 的 bridge）。

## 4. 理想形态（大胆版）

### 4.1 画板

```
┌ 项目栏 ─────┐┌ 素材墙（当前项目） ─────────────────────────┐┌ 拼盘 ──────────────────┐
│ ◉ 全局       ││ [全部][指令][技能][会话][Dot]  🔍  只看可疑 ☐ ││ 目标项目：webapp ▾     │
│ ○ webapp  12 ││ ── AGENTS.md › 构建 ───────────────── 3天前 ││ ① 构建约定   120 tok ≡ │
│ ○ api     5⚠ ││ ▢ 用 pnpm，不要用 npm         42 tok  [⋯]    ││ ② 部署一节   340 tok ≡ │
│ ○ docs       ││ ▢ 输出放 dist-old/  ⚠路径不存在 18 tok  [⋯]   ││ ③ @会话 修登录bug      │
│              ││ ── 会话 ──────────────────────────────       ││ ─────────────────────  │
│ 最近操作      ││ ▢ 修登录 bug        2 个月前  ⚠很久没动       ││ ████████░░ 1.2k / 8k   │
│ ↶ 移除 1 条   ││ ── 技能 ──────────────────────────────       ││ [预览] [复制] [写入…]  │
└─────────────┘└──────────────────────────────────────────────┘│ [▶ 用它开新会话]       │
                                                                 └────────────────────────┘
```

- **按项目分组**，项目旁显示素材数和可疑数。
- **每块拼图**带：类型色条、来源（文件 › 标题路径 / 会话标题）、新旧（文件 mtime 或会话时间，相对时间 + 颜色渐变）、token 估算、可疑标记。
- **操作**：勾选加入拼盘、拖动排序、移除（确认 + 可撤销）、复制到别的项目、展开看全文。
- **拼盘**：拖放排序、token 预算条（超预算变红并提示从哪块开始被截）、实时预览最终文本。
- **出口**：复制文本 / 写入目标项目的指令文件（带来源标记）/ 预填草稿开新会话 / 存为「配方」以后一键复用。

### 4.2 可疑度体检（只标不删）

| 信号 | 判定 |
|---|---|
| 路径失效 | 块里用反引号写的相对路径（如 `` `src/old/` ``）在项目里已不存在 |
| 重复 | 同一段文字（归一化空白后）在全局和项目、或多级目录里各出现一次 |
| 陈旧 | 所在文件 / 会话超过 90 天没变 |
| 被遮蔽 | `CLAUDE.md` 和同目录 `AGENTS.md` 内容一致——DSH 只会加载一份 |
| 超预算 | 整条指令链超过 `maxBytes`（默认 65536）会被 DSH 截断 |

### 4.3 远景（不在 v1.0）

- **配方**：保存拼盘为命名配方，按项目/任务类型推荐。
- **语义体检**：调用模型判断「这条约定和代码是否还一致」（需用户确认花 token）。
- **差异合并**：两个项目各有一版相同小节时做三方合并。
- **会话精华提炼**：选中一段会话，让模型提炼成一条约定再拼入（草稿 → 用户确认）。
- **真分词器**：接 DeepSeek tokenizer 给精确 token 数。
- **技能移植**：把技能目录整个复制到目标项目 `.agents/skills`（不覆盖同名）。

## 5. 安全边界

| 做 | 不做 |
|---|---|
| 读 DSH 已知会加载的位置（指令候选文件、技能根、会话、Dot 状态） | 不读任意路径；客户端传来的路径一律不信，服务端按「项目 + 素材 id」重新扫描定位 |
| 用户点「移除」并在确认框里再点一次，才改文件 | 不自动删、不批量静默删 |
| 改文件前把原文件完整备份到 `$DSH_HOME/context-studio/backups/<opId>/`，日志写入 `journal.json` | 不物理删除任何文件；会话只「归档」不删除 |
| 撤销时先比对文件当前哈希；被别人改过就拒绝并给出备份路径 | 不覆盖用户在这之后的改动 |
| 移除前核对文件哈希与扫描时一致，否则要求刷新 | 不在过期视图上改文件 |
| 写入只允许追加到目标项目根的 `AGENTS.local.md`（默认，通常不进版本库）或 `AGENTS.md`，用 `<!-- context-studio:begin … -->` 包起来、带来源 | 不改别处、不改 Dot 的数据、不改 preset |
| 开新会话只预填草稿 | 不自动发送、不调用模型、不碰 API key |
| 接口只接受本机同源请求，写操作要求 `X-Context-Studio: 1` 头 + JSON | 不对外暴露 |

原子写：先写同目录临时文件再 `rename`，保留原换行风格（CRLF/LF）和末尾换行。

### 拼好的起始上下文长什么样

```markdown
# 起始上下文

## 约定 · 来自 api / AGENTS.md › 部署
- 部署前先跑 `pnpm build`，产物在 `dist/`。

## 参考会话
- @[修登录 bug](dsh-session:Ij...In0)

## 会话摘录 · 修登录 bug（2026-10-02）
**助手：**
原因是 cookie 的 SameSite……

## 相关文件
- @src/auth/login.ts

---
（在这里写本次任务）
```

会话引用用 DSH 原生的 `dsh-session:` 提及，发送后由 `dsh-session-reference` 展开为有界只读快照；文件用 `@path` 提及，模型需要时自己读。

两处刻意的取舍（来自实测）：不加 HTML 注释头（它会原样出现在对话气泡里，块数和 token 只在拼图台界面显示）；摘录不用 `>` 引用（DSH 输入框会把引用块折叠成引用卡片，并吞掉紧跟的分隔线）。

## 7. 明确不做

- **改系统提示 / preset**：那是 profile 配置，改错影响所有会话；只在文档里说明去哪改。
- **删除会话日志**：只归档。
- **改 Dot 的记忆**：属于另一个插件的数据，只读。
- ~~fork 会话~~：v1.1 起在脉络图里提供「分叉」，用的是浏览器端 `ctx.uiWorkspace.forkSession(sessionId)`（`packages/client/ui-workspace/src/client/navigation.ts`），点击后先弹确认框。它带整段历史，适合「换个方向接着聊」；只想带一部分时仍用拼盘。

## 9. 实测记录（v1.0，2026-11-11）

实测中发现并修复的问题：

- **连续两次「开新会话」会让草稿叠在一起。** DSH 会复用工作区里还没发过消息的空白会话，第一版用的是 `whenDraftExists: 'append'`。现在改成先弹确认框，让用户选「接在后面（默认）」还是「替换」。复测后，选「替换」时草稿里只剩一份。
- 全局文件原来显示成很长的绝对路径，现在显示为 `$DSH_HOME/AGENTS.md`；「重复」标记也改成指向这个短名。
- 拼入的块原来直接显示 HTML 注释标记，现在只显示正文，并加上「拼入 · 来自 X · 日期」标签。
- 操作记录里的「写入」原来显示绝对路径，现在显示「项目名/文件名（来自 X）」。
- **会话摘录混进了运行时注入的消息。** `user/message` 事件不只有用户亲手发的，还有运行时注入的上下文快照、时间等，它们不带 `<system-reminder>` 外壳。现在通过 `sessionQuery.readSession()` 读到每条消息的 `source.kind`，只保留 `kind === 'user'` 的（来源：`dsh-llm` 的 `MessageSourceMap`、session-controller 的 `'user-rpc'`）；读不到时退回旧规则。
- **起始上下文的 HTML 注释头出现在对话气泡里，`>` 引用的摘录被折叠。** 现在去掉注释头，摘录改成「**助手：**」加正文。

已知限制：

- 网页版里点「添加工作区」会在宿主机上弹出原生文件夹选择框。实测时没有通过它添加工作区，而是在 DSH 停止时直接往隔离目录的 `storages/workspace.json` 里写入了两个工作区记录。这是实测环境的准备步骤，和插件无关。

单元测试：`npm test`，42 个用例全部通过。覆盖拆块、删块、追加、token 估算、扫描与体检、会话、备份与撤销、冲突检测、并发串行、日志损坏恢复、拼盘渲染、请求校验，以及一次挂到真实 HTTP 服务上的端到端流程。

## 10. 脉络图（v1.1）

### 10.1 为什么要改

v1.0 的素材墙按文件列块，用户反馈「可视化组织得不好用」：一堆卡片平铺着，看不出**哪些记忆和会话是一条链上的，哪些是独立的**，也就判断不了哪些能删、哪些该带走。v1.1 换了一个起点：**从会话出发**，先画出会话之间的分支关系，再看每个会话实际加载了哪些记忆。素材墙保留，作为看单块内容、移除、拼接的地方。

### 10.2 用的是会话日志里真实记录的东西

不靠文本猜测。下面每一条都在源码里核对过，也在隔离 DSH 的真实会话日志（`sessions/**/session.v4.jsonl.zstd`）里看到了：

| 关系 | 日志里的记录 | 源码出处 |
|---|---|---|
| 会话加载了哪份指令文件、哪个版本 | `user/message` 的 `source.kind === 'agent-instructions'`，`changes[] = { action: 'set'|'replace'|'remove', scope, path, digest }`；`digest` 是文件内容的 sha1；全局文件的 `path` 写成 `$DSH_HOME/…` 或 `~/.agents/…`，项目文件是相对项目根的路径 | `context/agent-instructions/src/index.ts`（`source: { kind: 'agent-instructions', … changes }`）、`digest.ts`（`instructionContentSha1`）、`files.ts`（`relativeDisplay`）、`util/home-paths`（`dshHomeDisplay` / `agentsHomeDisplay`） |
| 会话用过哪些技能 | 用户直接调用：`source.kind === 'skill-invocation'`，带 `name`；模型调用：`tool/call` 里 `name === 'skill'`，`arguments` 里有 `name` | `skill/tool-skill/src/index.ts` |
| 会话 A 引用了会话 B | `source.kind === 'session-reference'`，`references[].sessionId` | `context/session-reference/src/index.ts` |
| 分叉 | 会话头 `isSeeded: true`，继承的前缀以 `session/end-seed { inherited: true }` 收尾。普通分叉**不记录来源**（`parentSession` 只给子代理用），所以用继承前缀里用户消息的 `rpcId` 找回来源：哪个会话「亲手」发过最后一条被继承的消息，它就是来源 | `core/session/src/types.ts`（`SessionHeader`、`'session/end-seed'`） |
| 子代理 | 会话头 `parentSession` + `origin: 'subagent'` | 同上 |
| 拼图台开的会话 | 第一条用户消息以 `# 起始上下文` 开头 | 本插件 `compose.js` |

读日志用 `ctx.sessionQuery.readSession(id).events`。每个工作区最多读最近 `sessionLimit`（默认 50）个顶层会话及其子代理，总数不超过 300，并发 4。

### 10.3 模型

- **节点**：会话；记忆（指令文件按文件算，技能按名字算）。
- **会话之间的边**：分叉、引用、子代理，从来源指向后来者。
- **链路**：按这些边连通的会话组，至少 2 个会话。**独立会话**：没有任何这类边。
- **记忆的四类**，按「被谁用过」划分：
  - **共享**：被不同的链路或独立会话用过，是公共底座，比如全局 `AGENTS.md`；
  - **链内**：只在一条链路里用过，和这条链绑在一起，迁移这条链时要一起带走；
  - **单次**：只有一个会话用过；
  - **未用**：在读到的会话里一次都没被加载过。这是「可能过时」最直接的证据，比 v1.0 按修改时间判断陈旧更可靠。
- **版本**：日志里的 sha1 和文件当前内容的 sha1 比较。一致是「当前版本」（实心点），不一致或文件已删除是「旧版本」（空心点）。用过它的会话全是旧版本时，标「只被旧版本用过」。
- **排序**：DSH 会复用还没发过消息的空白会话，创建时间可能早于它引用的会话（实测遇到过），所以按**第一条用户消息的时间**排序。
- **焦点项目**：选中某个项目时，只显示和它有关的链路（链里有任何一个会话属于这个项目）和它自己的独立会话。别的项目的会话也会画出来，用空心节点和项目名标明，这样跨项目的链是完整的。

### 10.4 画面

```
┌ 1 条链路（4 个会话） 2 个独立会话   记忆：共享 3  链内 1  单次 1  未用 0  只被旧版本用过 1 ┐
│                                            $DSH_HOME/  AGENTS.  AGENTS  shop-api/  release │
│ ■ 链路 · 项目部署与数据库约定  跨 shop-api / shop-web                                        │
│ ◇      项目部署与数据库约定   shop-api        ●                    ●                         │
│ ◆┐     shop-api 周五可以发版吗               ●        ●       ○    │                         │
│ │◆     周五不能发布生产版本                  ●        ●       ○    │                         │
│ │ ○    项目部署与数据库约定 (1)  分叉         ●                    ●                         │
│ ■ 独立会话                                                                                   │
│ ●      加载 release 技能首步                 ●        ●       ○              ●              │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- 左边是泳道，像 git 图：一个会话的第一个后继沿用它的泳道，其余后继开新泳道，泳道用完会回收。实线表示分叉，虚线表示引用，点线表示子代理。◆ 表示由拼图台开的会话，空心表示别的项目的会话。
- 右边是记忆矩阵：每列一份记忆，列名竖排，列底色条标出它属于哪一类。同一条链里，一份记忆首末两次使用之间画一条淡淡的竖线（生命线），一眼能看出它贯穿了这条链的哪一段。
- **点一个会话**：高亮它的上游和下游，以及它加载过的记忆列，其他的变淡。底部详情里能看到：来自谁（分叉 / 引用）、延伸出谁、加载过的记忆（旧版本标「旧」）。可以做的事有：接着它开新会话（把它作为 `@会话` 引用放进拼盘，目标项目设成它所在的项目）、摘录、打开、分叉、归档。
- **点一列**：高亮用过这份记忆的会话；详情里说明它属于哪一类、哪些会话用过（当前版本还是旧版本）、有没有拼入的内容，并能跳到素材墙查看、移除。
- **点链路标题**：高亮整条链和它用到的全部记忆，可以把最近 3 个会话一次放进拼盘。DSH 一条消息最多展开 3 个会话引用（`session-reference` 的 `config.ts`）。
- 右侧拼盘在脉络视图里默认收起，让图有足够宽度；往拼盘里加东西时会自动展开。顶栏的「拼盘 N」按钮可以随时展开或收起。

### 10.5 安全

- 脉络图本身只读。
- **分叉**会在 DSH 里新建会话，所以先弹确认框，写明「复制到目前为止的全部历史，不会发送任何消息，不想要可以归档」。
- **归档**走 v1.0 的同一个接口：要求会话属于对应工作区，可撤销。
- **接着它开新会话**只是放进拼盘；真正开会话仍要经过 v1.0 的确认框，而且只预填草稿，不会自动发送。

### 10.6 已知限制

- 只看得到 DSH 日志里记录的东西。Dot 记忆由 Dot 插件自己注入，日志里没有统一的标识，所以不在矩阵里。
- 指令按**文件**算，不按块算：日志只记录了文件的 sha1。要知道某一块有没有被用过，要看素材墙。
- 「未用」只针对读到的会话（每个工作区最近 50 个）。
- 早于 v1.1 分叉出来、来源会话又已经找不到的分叉会话，会被当成独立会话。

## 11. v1.2：回答排查与上下文复用

### 11.1 产品目标和理想形态

工作台首先回答三个问题：这次输出前有哪些输入？它们来自哪儿、经历了什么变化？如果这条分析路线错了，应带哪些信息重新开始？

理想形态是以模型输出为锚点的时间图：用户问题沿主干前进，项目指令、引用会话、技能正文、工具结果从各自分支汇入；摘要和替换形成可展开的折叠节点。点击任何节点可看历史原文、来源、版本和预算，比较相邻两次请求的新增 / 保留 / 移除。用户可标注「缺失约束」「错误事实」「不相关信息」，把有用节点及备注组成一条新分支。自动诊断只能起草假设，不能替用户删除或改写记忆。

### 11.2 本版实现

- 默认入口改为「回答排查」。左栏选项目与会话，中栏选择具体回答（模型每一步均可选），右栏按需打开新会话草稿。
- 来源流向显示用户要求、注入上下文、系统指令、历史输出、工具结果如何组合到这次输出前；点击来源类别可定位原文。
- 在选定回答的序号之前处理 `surfaceOp`。append 放尾部；replace 按当前消息位置替换闭区间，原文进入「已替换」，保留直接替代者和 `sourceEventSeqs`。列表使用模型历史位置而非简单按 seq 排序。
- 「新增」指序号不早于上一次模型输出的现存记录，包括上次输出及后续工具结果。它表示新的输入记录，不推断语义影响。
- 工具通过 `tool/call.data.callId` 与 `tool/result.data.message.toolCallId` 配对。显示历史返回文本和调用参数，`isError` 为真才自动标工具错误。
- 线索来自明确记录：引用的 `truncated / omittedMessages`、指令 `replace / remove`、结构替换、回答 `interrupted`、重试 / 未完成尝试、展示截断、图片卸载。无自动语义因果判断。
- 原文支持局部选中文字。选中的文字作为 snippet，标题含会话 / 来源 / seq，正文前保留会话 ID 和事件编号；已替换的原文额外标注历史状态。不会自动添加整会话引用。
- 点击开新会话时重新 compose 最新素材与任务，再由确认框调用原生 `startSession`；默认追加已有草稿，等待完成，不自动发送。
- 统一留白、字体、颜色和焦点；来源列表与详情在窄容器内上下排列，极窄窗口的草稿下移。沿用备份 / 撤销和本机同源守卫。

### 11.4 安全与解释边界

- 历史检查不读取现在的项目文件来填补过去；未来消息、未来替换和未来请求头不会进入所选回答的上下文。
- 这是回答前日志消息**位置**的重建。不能保证完全等同供应商发送时的请求（适配器转换、并发注入、图片卸载、工具 schema、隐藏推理等不在此视图还原）。不显示「模型一定看到了 / 依据了」这样的推断。
- 未识别的位置放到「位置未知」，不会伪装成有效输入。`image/offload` 只提示限制，不尝试执行投影。
- 只返回可见文本及必要元信息，不返回完整请求头、原始 stream、reasoning、工具内部 meta。不进行 API key 读取或模型生成调用。
- 每条可见文本最多展示 20,000 字符，明确标注；token 估算仍按完整可见文本计算。超过 50,000 条事件拒绝处理。不会悄悄截断日志前缀再声称完整回放。
- 选中片段和任务存在本机浏览器 localStorage。复制 / 预填 / 写入均为用户动作，源日志不改；原有指令文件备份及冲突保护继续有效。
- 当前只做来源分类和位置变化。下一版再做相邻请求文本 diff、人工问题标注和更完整的供应商投影。无告警不能代表答案正确。

## 13. v1.3：模块化排查与长历史分页（2026-11-16）

### 13.1 问题与交互设计

用户反馈“历史上下文超过检查容量上限”，以及 context 流程缺少模块化、难以操作。旧 Inspector 在导航出现前就拼接整段可见正文，达到 2,000 条输入或 100 万累计字符便返回 413；保护机制导致连选择更早回答也困难。

理想交互以问题为线索：先定位偏离预期的回答，再看用户目标、项目约定、引用、工具证据如何汇入，比较与前一次回答的变化。用户应能从模块找到历史原文，标注问题并决定带哪些内容重新开始。模块的“在输入中”只说明日志位置，不代表可信或正确；自动线索不能替代用户判断。

本版将阅读分成四步：**会话 / 回答 → 输入模块 → 记录 / 原文 → 新会话草稿**。六个主要模块是用户要求、项目约定、引用会话、工具结果、历史回答、技能；系统与环境和其他来源按需展开。无记录模块弱化折叠，已替换和位置未知单独筛选。选模块后收起目录、定位记录区，原文在侧面详情中打开，支持 Escape 关闭并恢复焦点。主要模块在 1440×900 的实际插件区域内首屏可见。

该版先解决定位、阅读和复用。相邻请求的文字 diff、人工标注与可自由编排的因果图仍为后续设计，不把来源分类声称为模型内部注意力或推理图。客户端设计细节见 [模块化 UI 设计](DESIGN-ui-1.3.md)。

### 13.2 后端与数据契约

新增 `context-view.js`，仍只使用已确认的 `sessionQuery.readSession()`，没有新增猜测的 DSH 服务。首次读取依然由宿主完成整份日志加载；随后位置索引只保留事件引用和 append / replace 关系，不拼接全部历史正文。合法替换用链表位置处理，索引分段让出事件循环。

### 13.3 完整性与安全

- 普通长文本不再受旧累计正文容量限制；每页只返回当前片段，分页本身不标为不完整。
- 所选回答前超过 250,000 条事件时，模块计数标记不可用，保留回答导航和答案原文入口。不能显示为“0 条上下文”。
- 单条最多处理 100,000 个内容块；对象形式参数累计最多 2,000 节点 / 100,000 字符 / 16 层。超限明确标记未展开；字符串正文和参数仍可分页。附件与未知内容块不展开。
- 来源集合检查最多 50 项，展示引用/变更各最多 30 项、来源事件最多 50 项。畸形字段与过多关联明确提示，不把无法读取说成不存在。
- 不返回请求头、stream、隐藏 reasoning、附件载荷；可见正文自身不是通用秘密脱敏器。页面不调用模型，不读取或填写 API key。
- 所选片段以会话、事件、正文/参数、绝对起止偏移去重。相同文本在不同页可单独加入；只加入用户实际选中部分，草稿只预填、不发送。token 只估算当前原文页或所选草稿，不编造全历史总数。
- 浏览器正常使用前后页游标。直接调用 API 输入任意 Unicode 中间偏移时会校正起点，但再向前翻页可能重叠少量文字；仍返回准确范围与对应原文，不丢内容。这是当前开发接口限制，UI 不提供随机偏移输入。
- 初次宿主完整日志读取、有限缓存的字节容量、同步目录统计成本仍需性能优化；应用超时不能抢占宿主底层 I/O。保护预算不等于无限历史能力。

用户希望保留原始信息，同时允许主动使用 token 把当前会话整理成人能读懂的内容，并提出相关建议。新的默认入口为“会话整理”，图保留在“原始记录”。进入页面和查看旧报告不触发生成；独立客户端设计与实现见 [UI 设计](DESIGN-ui-1.5.md)。

主路径是**选会话和模型 → 预览实际发送快照 → 确认消耗 → 阅读五类卡片 → 核对来源 → 选择建议及原文建立草稿**。可填写关注点，默认整理到最近一次已记录回答，也可在原始图选择“整理到这一步”。改变供应商、模型、范围或预算都会要求重新预览。已完成报告优先显示正文，运行中或失败的作业保留明确的状态出口。

五类为目标与约束、已有结论、关键证据、待核对、建议下一步。全部是模型派生文本，不把“已有结论”说成经插件验证的事实。疑点只能作为核对假设；来源链接只保证编号属于本次提供的材料，不能证明模型正确理解了该材料，更不能证明内部因果。

建议以“AI整理建议（待核对）”便签加入分支，记录报告与会话来源；不自动替换任务。历史原文是另一项明确选择，保留实际文字区间。所有新会话操作仍经过已有确认，仅预填，不发送、执行命令或修改 memory。

### 15.3 输入快照、范围与容量

沿用原始图的历史位置索引，读取所选回答之前的 active/replaced/unknown 记录，并加入答案本身（状态 answer）。原文由可见文本投影取得，不返回隐藏推理、原始流、请求头或附件载荷。系统与环境记录默认排除，项目指令仍作为单独 memory 材料纳入。

默认估算输入预算16k，可选8k/32k；输出上限默认4096，可选2048/8192。优先当前回答、用户要求、项目约定、引用、技能，再考虑工具及其他历史；同类偏向较近记录。最终按 seq 排序，保留来源类别、状态、offset/end/totalChars。最多80条，每条最多8,000字符；预算不足会继续缩短或省略，Unicode 码点不被拆开。确认前可查看完整 system 和输入 JSON，coverage 明示纳入、截短、省略、排除系统记录。

这是有损选材，不是读完全部历史或精确 tokenizer。所选回答后尚未回复的输入不会进入本次快照；预算选择也不是对所有材料的语义完备保证。超过25万结构事件的索引不返回伪完整结果，应在原始记录选更早回答。底层 readSession 仍先读取完整日志，这一步的内存与 I/O 成本尚未消除。

### 15.4 API 与一次调用语义

路由前缀 `/api/dsh-plugin-context-studio`，仍受同源、回环及写请求头保护。

| 接口 | 行为 |
| --- | --- |
| GET organize-models | 只列 id/name，可用性与目录警告，30秒缓存 |
| POST organize-preview | 校验模型和预算，读取历史并创建5分钟有效的计划；最多保留4份；零生成 |
| POST organize-start | 只接受 planId 与 confirmed:true；计划ID同时是作业ID；返回状态后后台运行 |
| GET organize-job | sessionId + id 读取状态、已知用量、来源与报告 |
| GET organize-history | 当前会话最近10份作业摘要，不会重新生成 |
| POST organize-cancel | 请求 AbortController 停止，可继续查询；已消耗 token 无法撤销 |

先用排他原子写入保存 durable receipt，再 prepareCall/stream。同一计划的并发请求、成功、失败、取消和重启后均返回既有作业，绝不重放。写入 receipt 失败则零调用；写入等待期间停止插件或更换模型实现，保留取消凭据且不派发。最后结果保存完成或明确失败后才向 UI 公布终态，避免轮询提前停止而漏掉保存警告。

本实例最多一个未结束的宿主调用。180秒超时或取消请求中止；供应商忽略 abort 时继续占位，防止叠加调用。宿主重启看到 running receipt 时标 interrupted，不自动补跑。该限制不是跨进程全局限流；同一 dataDir 的不同进程可能有不同作业同时运行。

模型结果只接受有界 JSON 和五类卡片，最多20张，去除额外字段；来源必须在提供列表中。异常 JSON、工具请求、超长流、无 finish、非 stop、终止后额外事件均失败，无自动重试。供应商原始错误不直接回显，防止连接信息泄露。实际 usage 取已返回的最新安全字段，没有就显示未知，不能把失败说成零费用。

### 15.5 存储与信息边界

报告与本次来源片段存入 `<dataDir>/organize/<会话ID的SHA256前32位>/<唯一作业ID>.json`，默认 dataDir 为 `$DSH_HOME/context-studio`。同文件先存凭据，再保存结果；原会话与项目文件不修改。浏览器只保存已有草稿与偏好。保存失败时结果留在内存并明确提示复制，重启后可能只剩 interrupted 凭据。

上下文中包含指令并不意味着整理模型可以执行：系统提示把历史当待分析数据，tools 为空，不提供执行器。建议作为不可信文字渲染，不能触发页面脚本或外部操作。可见文字自身可能含秘密，确认面板不是自动脱敏器。用户确认的快照将发给其所选模型供应商，插件不接收或填写 API key。

## 16. v1.5.1：OpenCode 整理失败定位（2026-11-16）

### 16.1 已知事实与结论边界

用户本地失败作业使用 `opencode-go / deepseek-v4.1-flash`，约3秒后退出；输入估算7,995 token、输出上限4,096，选入16条材料、截短1条、排除6条系统记录。失败发生于模型响应阶段，尚未进入简报解析，不是历史检查容量上限。旧代码只保存了“模型未正常完成整理”，没有保留 `finish.reason.failure`，无法据此还原真实上游错误或认定零费用。

查到一个确定的兼容缺陷：v1.5 一次性整理未传 `sessionId`，安装版 DSH 的 OpenCode 适配链因此不添加会话路由头。Go 要求稳定的会话标识，见 [OpenCode 官方说明](https://opencode.ai/docs/console/harnesses)。该缺陷能解释快速拒绝，但旧错误原文已经丢失，不能排除其他上游问题。

### 16.2 源码核对与实现

- `llm/llm-pi-ai/tests/adapter.spec.ts:196–213` 已有 Go 请求按 sessionId 传递路由头的宿主测试；`src/adapter.ts:456–469` 将它透传给 `streamSimple`。
- 安装版 `@earendil-works/pi-ai/dist/providers/opencode-go.js` 使用 `withOpenCodeSessionHeader`；同目录 `opencode-headers.js` 只有 `options.sessionId` 存在时才补 `x-opencode-session`，已有同名请求头则保留。插件不自行改供应商配置或覆写请求头。
- `llm/llm-pi-ai/src/stream.ts:42–128` 将供应商错误映射为固定分类，通过 `finish.reason.failure` 返回；流错误不一定抛异常，usage 也可能仍是初始化的0。

第15节的一次性调用约定在 v1.5.1 调整为：仅对 `opencode-go` / `opencode`，传入 `context-studio-organize-` 加来源会话ID哈希前32位的稳定辅助标识。同会话多次整理标识不变，不同会话分开。它是请求路由元数据，不是原生 DSH 会话；原会话不写入，模型仅收到确认过的快照，tools 为空，purpose 仍为 `context-studio-organize`。其他供应商不新增 sessionId。

`safeModelFailure` 只输出固定分类和建议，允许的有限 HTTP 状态可以保留；供应商原始消息不保存或回显，也不根据其中的关键词猜测更具体的原因。优先保留宿主的已知分类，缺少分类时使用允许的状态码，否则标记未知。作业增加 `diagnostic`，记录 `model-prepare / model-stream / report-parse`、已知结束类型和收到的文字长度。重复确认、取消、重启和失败不自动重放的语义不变，旧作业不补造诊断。

**第 17 节的三列任务地图主 UI 已由本节取代**，旧章节保留当版记录，不作为当前交互规格。当前采用已批准的 Git 分支式控制台：左侧路径/待核对/派生草稿，中间前缀树画布，右侧详情与源对照，底部新起点。Git 分支只是视觉表达，不是 Git 操作、真实历史分支或执行因果。完整规格见 [DESIGN-ui-1.7](DESIGN-ui-1.7.md)。

### 18.1 卡片与路径

卡片保留 title/body/evidence，新增可选 summary（180）、scope（120）、caveat（160），长度以 UTF-16 单元计；title 仍限 100。state 只接受 recorded/hypothesis/conflict/superseded/null，全部作为 AI 标注：有记载不等于已验证，冲突/失效仍待核对。短卡优先显示 summary，缺失时视图回退 body，不补写报告字段。

paths 只来自模型显式输出，最多 8 条、每条 1–20 个不重复节点；端点必须是已保留且原 ID 唯一的卡片。重复/歧义 ID 校验覆盖被过滤及超限项，坏节点使整条路径失效。解析输出 path-n 与 card-n，详细规则见 [REPORT-CONSOLE-CONTRACT](REPORT-CONSOLE-CONTRACT.md)。新调用 templateVersion 为 3，存储 version 仍为 1，旧报告不迁移、不补生成。

前端以完整前缀作为实例键，只合并完全相同的前缀；A→B→D 与 A→C→D 的 D 是不同实例，分歧后的共同后缀不能重新合并。允许不同根。旧报告无 paths 时采用 free 自由选材布局，仅显示已有有效 AI 关系和实际共同引用，不按 category、标题或位置伪造路径。

### 18.2 选材、源对照与草稿

「选用整条链」按当前路径选择；「选用到这里」按当前实例前缀选择；局部勾选只带用户明确选中的卡片。state.instances 保存选择时的前缀实例，与当前浏览路径分离，不因点击另一条路径而改变。缺少前缀或明确 depends_on 目标时仅提示，允许用户继续局部选择；只有明确点击补选才增加材料，不自动扩选。

节点详情展示正文、适用范围、注意事项、AI 关系和原文依据。来源先在图内显示本报告保存片段、seq、字符范围及截短情况，需要时进入原始记录。原文只从已校验的 sources 取用，可自动附带所选卡片引用，也可单独删选；引用有效不证明判断正确。

流程为「整链/到此节点/局部 → 新 context 配置 → 完整草稿预览 → 用户确认」。地图选材与旧 board 隔离。取消预览不生成 trace；确认后只预填目标工作区草稿，默认 append，也可明确 replace，不自动发送。无预填能力时确认后只复制。目标项目指令仍由 DSH 加载；浏览已有报告和派生草稿不调用 LLM。

### 18.3 派生 snapshot

成功预填或复制后才将 snapshot 写入本浏览器 localStorage，保留所选节点、原文、路径实例、来源报告/会话、任务、目标及当时完整 prompt。键为 dsh-context-studio:context-drafts:v1；保存上限 20 条，序列化数组不超过 500000 个 UTF-16 单元，超限先淘汰最旧项，单份仍过大则提示未保存。存储失败不撤销目标草稿。

返回报告可查看和恢复选材；snapshot 是当次草稿来源，不是 DSH 原生 fork、后续对话或目标输入框的实时镜像。未确认选择仍使用最多 6 份模块内缓存，不与持久化 snapshot 混同。恢复后再次使用仍需预览确认。

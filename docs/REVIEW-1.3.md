# v1.3 工程校验与剩余不足

日期：2026-11-16。基线：e987843（本地 v1.2.1）。当前版本：1.3.0，本地改进，未推送或发布。

本次修复针对长历史容量错误和难用的 context 流程。由一个客户端实现子代理、一个独立后端审查子代理和主代理协作完成；不是第三方认证，也不声称穷尽全部缺陷。底层 DSH 接口仍以源码核对为准。

## 结论

新版 Inspector 不再调用整段 `/inspect`，改用结构目录、模块记录页和按需原文页。超过旧版累计条目 / 正文上限的合成历史可以导航并读取末尾；普通分页不显示成不完整历史。真实隔离 DSH 已走通选择回答、选择模块、核对工具结果及来源、局部摘录和预填新会话。

当前 **203/203 node:test 测试通过，0 跳过、0 TODO**。另有 client/context-view 语法检查、`git diff --check`、`npm pack --dry-run` 通过。打包包含新后端文件；无新增运行时依赖。

## 发现与修复

| 问题 | 修复与证据 |
| --- | --- |
| 旧容量保护阻断整个排查页 | 目录与正文分离；2,300 条输入、单条 120 万字符、HTTP 尾页均有回归。极端事件上限保留回答导航，计数明确不可用。 |
| 模块不清楚、点击后反馈弱 | 主要来源分卡片；点击收拢目录并定位记录；原文侧面打开。回答预览、导航、空模块和系统背景收紧，首屏可见主要模块。 |
| 无回答会话误把 boundary 当回答 seq | 无 assistant 时省略 answer；模块切换与详情读取有客户端回归。 |
| 迟到请求串页、重复文本去重错误 | 目录与原文请求分开取消和核对身份；选择使用实际范围，以会话/事件/原文部分/绝对区间去重。 |
| 缓存淘汰后定时器仍持有日志（R1） | 淘汰清定时器，已淘汰 pending 不再建定时器；独立 GC 子进程验证至多保留两份。 |
| 畸形来源被默认为空（R2/R2b） | 集合和白名单字段类型校验，明确不完整；省略数字不隐式转型。 |
| 中断回答丢失标记（R3） | 回答、目录、详情和警告保留中断线索。 |
| 分页拆开 emoji（R4） | 顺序页保持 Unicode 码点，拼回原文无遗漏；原文与字符来源使用实际校正偏移。 |
| 对象参数累计计算缺少限制（R5） | 对所有对象参数共享节点/字符预算；大数组来源仅查有限项并提示。原先 1,500 个大参数反例已转为回归。 |
| 工具结果来源链接无法打开 | 增加历史前缀内的只读 tool/call 原文；只投影调用名与参数，伪造嵌套 message 的合成敏感字段不返回。 |

具体复现、二次验证和局限见 [独立后端报告](REVIEW-1.3-backend.md)；客户端设计与 28 项 VM 回归见 [UI 说明](DESIGN-ui-1.3.md)。前版写入/恢复问题的状态仍见 [v1.2.1 汇总](REVIEW-1.2.1.md)。

## 仍存在的不足

| 优先级 | 剩余事项 | 当前边界 |
| --- | --- | --- |
| P2 | 宿主完整日志读取与内存 | readSession 不是流式 API，首次完整读取/克隆仍可能慢；两份缓存按数量限额，没有字节权重。超时不能中止宿主 I/O。 |
| P2 | 超大目录计算 | 250,000 条前缀保护与有限元数据扫描降低成本，但不能承诺任意大日志的即时响应。 |
| P2 | 快照版本一致性 | 页请求没有固定快照版本游标；正常前缀不可变是前提。宿主主动修复历史时，缓存过期后的跨页一致性尚待专门验证。 |
| P2 | 原生桌面与可访问性矩阵 | 隔离浏览器通过不代表所有桌面版本、高 DPI、屏幕阅读器均已通过。原有写入确认框完整焦点管理仍待改进。 |
| P3 | 任意偏移的反向页游标（R4b） | 直接传入非正常翻页生成的 offset 后，“上一页”可能少量重叠。返回范围与原文仍对应；UI 没有任意偏移输入，从头顺序翻页已验证。组合字/ZWJ 字素仍可能跨页。 |
| P3 | 模块只是来源组织 | 尚无相邻回答文字 diff、人工问题标注或模型内部注意力图；搜索仅标题/预览。重新进入插件还需选择会话。 |

原有文件改动的最终外部编辑竞争窗口、崩溃遗留协作锁恢复和备份清理向导属于前版已记录的不足，本次没有扩展写入功能。页面中的风险标记是核对线索，不能证明答案正确或错误的内部原因。
